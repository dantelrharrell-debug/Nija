# NIJA Mobile App - Build & Deployment Guide

**Status date:** 2026-08-27

This is the canonical build guide for the NIJA iOS and Android store clients. Store-console, signing, organization-verification, counsel, and physical-device actions remain external dependencies.

## 1. Permanent application identifiers first

Do not finalize store registration, signing, Firebase/APNs registration, app/universal links, or associated domains against a temporary identifier.

Before production packaging, approve:

- iOS bundle identifier: **PENDING FINAL OWNER DECISION**
- Android application ID/package: **PENDING FINAL OWNER DECISION**

Replace any historical `com.nija.trading` examples only after the permanent IDs are approved.

## 2. Required tools

### iOS

- Current supported macOS and Xcode for the submission SDK.
- Apple Developer Program organization/account access.
- Valid signing/provisioning configuration.

### Android

- Current Android Studio/JDK supported by the generated Capacitor project.
- Android SDK Platform 36 installed.
- Google Play organization/developer account access.

### Shared

- Node.js/npm versions supported by the repository lockfile/tooling.
- Capacitor dependencies installed from the repository.

## 3. Generate native projects

The native projects are generated by Capacitor and are not currently committed as a complete production Android/iOS project in this repository.

```bash
npm install
npm run cap:add:ios      # when iOS project does not exist
npm run cap:add:android  # when Android project does not exist
npm run cap:sync
```

Do not upload a store build immediately after generation. Apply the platform release gates below first.

## 4. Android release configuration

Google Play requires new apps and updates submitted after **2026-08-31** to target Android 16 / API level 36 or higher.

After Android generation, the effective app Gradle configuration must include:

```gradle
android {
    compileSdkVersion 36

    defaultConfig {
        applicationId "FINAL_NIJA_APPLICATION_ID"
        minSdkVersion 23
        targetSdkVersion 36
        versionCode 1
        versionName "1.0.0"
    }
}
```

Then run:

```bash
python scripts/validate_mobile_store_readiness.py --strict
```

A production release is blocked unless the validator confirms both `compileSdk >= 36` and `targetSdk >= 36`.

### Android permissions

Start with the minimum set required by shipping features, for example:

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
<uses-permission android:name="android.permission.USE_BIOMETRIC" />
```

Do not add legacy broad storage permissions or call-log permissions without a reviewed feature requirement and corresponding privacy/store disclosure update.

### Android security

- `usesCleartextTraffic=false` in production.
- No signing keys, passwords, service credentials, API secrets, or broker secrets in the client repository.
- Use Google Play App Signing or the approved secure signing process.
- Test the release AAB on Android 16/API 36 and on supported minimum-SDK devices.

## 5. iOS release configuration

After iOS generation:

1. Apply the permanent bundle identifier.
2. Select the correct Apple Developer organization/team.
3. Configure only required capabilities, including Push Notifications/associated domains when actually used.
4. Keep production secrets out of the app bundle.
5. Confirm privacy-manifest and required-reason API obligations for the shipping SDK/dependencies.
6. Archive and validate the exact release build in Xcode before App Store Connect upload.

## 6. Push notifications

### Android / FCM

- Register the final Android application ID in Firebase.
- Provide production `google-services.json` through the approved build process.
- Keep FCM server credentials server-side.

### iOS / APNs

- Register the final iOS bundle ID/capability.
- Configure APNs key/certificate securely outside source control.

NIJA's backend device registration is authenticated and uses persistent encrypted push-token storage. Production must use durable storage and account deletion/logout must remove applicable device records.

## 7. Data Safety / App Privacy release audit

Immediately before each store submission, reconcile the exact release binary and backend against `mobile/DATA_INVENTORY.md`.

Required audit areas include:

- account/authentication data;
- broker credentials and broker account/trading data;
- subscriptions/purchases;
- device identifiers and push tokens;
- analytics/crash telemetry;
- support/marketing integrations;
- any AI/LLM provider or prompt/context transmission;
- retention and account-deletion behavior.

Do not reuse old store-form answers when the implementation or vendor set changed.

## 8. Third-party AI integration gate

The inspected `education_system.py` AI explanation path is currently a placeholder/TODO, not an enabled outbound provider call.

Before any OpenAI or other AI/LLM integration is enabled in a release, the same change must update:

- `mobile/DATA_INVENTORY.md`;
- privacy policy/data disclosures;
- Apple App Privacy and Google Data Safety review notes;
- processor/vendor inventory;
- consent/disclosure behavior where required;
- retention/deletion handling;
- controls preventing broker/API credentials and unnecessary financial data from entering prompts.

## 9. Google Play account gates

Before production rollout:

- Complete organization/developer verification applicable to NIJA.
- Confirm the permanent application ID is registered correctly.
- Complete the financial-features declaration accurately.
- Complete Data Safety from the shipping implementation.
- Provide the required external account-deletion method in addition to the in-app flow.
- Provide reviewer credentials/instructions when authentication blocks review.

## 10. Apple account/legal gates

Before production rollout:

- Accept applicable Apple Developer agreements.
- Complete App Privacy from the shipping implementation.
- Provide reviewer access and clear review notes for financial/trading functionality.
- Confirm subscription/payment implementation is permitted for the intended storefronts.
- For EU distribution, review the August 2026 EU business/payment terms and obtain product/counsel approval for the selected payment path.

## 11. Build commands

### Android

```bash
npm run cap:sync
python scripts/validate_mobile_store_readiness.py --strict
cd android
./gradlew bundleRelease
```

### iOS

```bash
npm run cap:sync
npm run cap:open:ios
```

Archive the Release configuration in Xcode and validate it before upload.

- [ ] Permanent iOS/Android IDs approved and applied.
- [ ] Android validator passes API 36 requirement.
- [ ] Release build tested on physical/representative devices.
- [ ] APNs/FCM production configuration completed securely.
- [ ] Privacy policy and store declarations match the release.
- [ ] Account deletion verified end-to-end across NIJA-controlled stores.
- [ ] Reviewer account/instructions tested.
- [ ] Apple/Google organization and agreement requirements completed.
- [ ] Counsel has approved unresolved financial-services/legal classifications and public legal documents.
