# NIJA website lead attribution reconciliation

## Purpose

Stop reporting inflated website form events as paying customers or qualified leads.
This audit observes actual rows in the canonical Render `website_leads` table;
it does not modify leads, deliver customer email, submit advertising events, or
certify completeness. Never expose contact records or a private database file.

## Existing events are **not** equivalent

On October 29, 2026, connected analytics for October 1-29 reported:
- GA4 `ads_conversion_Submit_lead_form_1`: 2,800 event occurrences.
- GA4 `lead_created`: 9 event occurrences.
- GA4 `founding_100_application_submit`: 1 occurrence.
- GA4 `pilot_application_submit`: 1 occurrence.
- Google Ads `Nija AI Trading` conversions: 2,620.
- Its primary conversion action is `Lead form submitted` (a GA4 custom
  conversion), *not* a verified customer/payment count.

None are individually confirmed, deduplicated CRM records. Investigate
why the ad optimization signal fires without a corresponding persisted lead.
Events may be double counted, misconfigured, imported incorrectly, or
generated by low-quality traffic; do not assume fraud without evidence.

## Read-only evidence count

Run **only in the authenticated environment that actually holds the original
persisted lead file**. Example:

```sh
python website_persisted_lead_audit.py --database /app/data/nija_outreach.sqlite3 --period 2026-10
```

The script resolves an **existing** file and opens SQLite with `mode=ro`.
It prints only counts for server receipt-month, distinct submission IDs,
distinct contact emails, and safe form categories. An unmatched or missing
source is an error, **not zero leads**. It never transmits data or outputs PII.
`NIJA_LEAD_DB_PATH` or `NIJA_OUTREACH_DB_PATH` may override the default;
confirm the actual authoritative path from restricted production config.

A row's presence is only an intake observation; it is **not** evidence that
marketing consent was granted, that Google Analytics is permitted to receive
an event, that a customer is a paying member, or that all other IONOS forms
are represented. The direct form submission API is protected by a secret,
with deduplicated persistence and independent Zapier/Apollo forwarding.

## Conversion correction gate

1. Compare persisted submission IDs and form categories against IONOS's
   authoritative form store, Zapier catch-hook history, Apollo contacts and
   first-party analytics for a matching reporting window.
2. Reject duplicates, tests, bounced addresses, bot/spam forms, and opt-outs;
   define qualification separately from submission.
3. Ensure a separate valid analytics consent/measurement basis, GA4 client
   attribution identifiers, and documented data-collection controls.
   Communications/marketing consent is **not** automatically analytics consent.
4. Stage `nija_verified_lead` only from a saved and verified record, using the
   existing `analytics.verified_conversion_events` and
   `analytics.conversion_outbox` without PII. Network delivery is
   deliberately disabled unless provenance, deduplication, consent and
   attribution have been audited.
5. Reconcile completed Stripe/ClickBank payments, refunds and processing fees
   separately; GA4 `checkout_complete` and trial signups are not revenue.
6. Replace Google Ads' primary `Lead form submitted` optimization action
   only after the new server-verified conversion is correctly configured and
   received on a test event. Never count `ads_conversion_Submit_lead_form_1`
   as an independently verified lead.
7. Keep the NIJA Google Ads campaign paused while conversion and location
   targeting are unverified. As of October 29, the campaign was paused and
   targeted the United States, but its location option was still
   `PRESENCE_OR_INTEREST`. Presence-only targeting was not yet established.
8. Don't restart paid acquisition until actual attribution, traffic quality,
   acceptable acquisition costs and a verified checkout conversion path pass.

## Profitability linkage

A source lead-count audit may inform reconciliation but must **not** set
`qualified_leads_verified` or `counts_complete` to true. The signed
`website_profit_reporting_api` supports a certified aggregate visitor/lead
count only after independent GA4/CRM validation and matching-period revenue
and all expense allocations. This script by itself does not activate profit
reporting or make a profitability claim.
